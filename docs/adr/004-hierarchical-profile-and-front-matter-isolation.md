# ADR-004：四階層 Profile 繼承體系、前言獨立切分與純淨 Chapter 1

- **狀態**：Accepted
- **日期**：2026-10-22
- **Agent**：`antigravity`
- **任務**：`TASK-013`, `TASK-014`

## 1. 背景與問題

過去書籍轉換流程中存在三大結構性問題：
1. **設定命名與型別混亂**：書籍輸出為 `book_profile.json`，論文輸出為 `document_profile.json`，缺少強型別驗證與統一 Schema，難以進行跨文獻幾何與特殊區塊繼承。
2. **前置頁面污染正文**：許多教科書因 PDF 書籤粗糙，將 `Chapter 1` 標記在第 1 頁，導致 Chapter 1 吸收了封面 Cover、版權頁、目錄 TOC 與前言 Preface 等前置頁面。
3. **並發校準爭用**：Profile 建立邏輯埋在單章轉換中，多核心平行運算時可能引發競爭寫入。

## 2. 評估過的方案

| 方案 | 優點 | 缺點 |
|---|---|---|
| A. 保持動態字典與各自命名，章節各自抽樣 | 零重構成本 | 欄位不一致、並發寫入衝突、Chapter 1 混入封面雜訊 |
| B. 建立純領域層強型別 `DocumentProfile`、統一 `profile.json`、獨立 Front Matter 切分與獨立階段校準（採納） | 100% 型別安全、徹底純淨 Chapter 1、無併發爭用、相容舊版鏡像檔案 | 需重構分析器、協調器並維護鏡像寫入機制 |

## 3. 決策與理由

採用**方案 B**：
1. **統一主檔名與向後相容**：主設定檔統一為 `profile.json`，並為舊工具維護鏡像檔案。
2. **三層共享知識體系 (Level 3)**：引入 `front_matter_taxonomy.json` 與 `pedagogical_blocks.json`。
3. **純淨 Chapter 1 與前置頁切分**：自動向後探測真實 Chapter 1 起始頁，前方所有頁面獨立切出為 `00-` 編號之獨立 PDF 並全面轉為 Markdown。
4. **獨立階段校準**：在切分後、轉換前單執行緒建立 `profile.json`，嚴格排除 `00-*` 樣本。

## 4. 影響與代價

- **正面影響**：書籍章節閱讀與雙向導航體驗完整且精確，排版幾何（奇偶頁非對稱、跨欄橫幅、字級階層）具備強型別約束與閉環自我修復能力。
- **代價**：新增了共享知識庫資源檔與領域層驗證，需維持 100% 單元測試覆蓋。
